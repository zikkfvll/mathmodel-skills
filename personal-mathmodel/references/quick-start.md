# 使用指南

这套工作流采用一个总控对话，以及每问的研究审核与执行两个对话。四个技能按职责调用，共享资料通过项目文件交接。

## 第一次使用

按 [安装说明](https://github.com/zikkfvll/mathmodel-skills/blob/main/docs/installation.md) 将四个完整模块安装在同一个技能根，保持目录名称不变。安装后，在 Codex 中使用 `$personal-mathmodel` 作为总控入口。

提供题面、附件位置、截止时间、官方格式，以及已有想法。总控先讨论总体方向，等使用者提出具体问题后再组织对应研究组。有现成资料索引、数据口径和结果时先复用，不从头读取整套附件。

| 模块 | 职责 |
|---|---|
| [personal-mathmodel](../SKILL.md) | 整体方向、各问关系、共用资料与跨问影响 |
| [personal-mathmodel-modeling](../../personal-mathmodel-modeling/SKILL.md) | 本问理解、两轮讨论、论文学习、方法取舍与验证设计 |
| [personal-mathmodel-coding](../../personal-mathmodel-coding/SKILL.md) | 按确认方案实现、运行、制图和返修 |
| [author-mathmodel-writing](../../author-mathmodel-writing/SKILL.md) | 作者文风、同方法表达、正文、排版与核查 |

只做局部写作或代码任务时，可以直接调用相应模块。

## 一问的推进过程

1. **自由讨论。** 先聊研究对象、希望得到的答案、直觉和难点。
2. **AI 检索与阅读。** 围绕具体问题搜索相关论文，说明读到了什么、方法的适用条件和可借鉴之处。
3. **使用者补充。** 补充学校电子图书馆入口、找到的论文和新想法；登录由使用者完成。
4. **第二轮讨论。** 对照题目、数据与文献，比较少量可行路线，共同确定方案。
5. **实现与复核。** 执行方实际运行并回传产物，研究审核方核查关键结果；发现问题后做相关返修。
6. **写作与交接。** 从确认的结果取数和作图，完成连续论述，再说明对下一问的影响。

每问约20篇是可调整的学习目标，六类来源合并去重计数。核心是相关原文及其判断依据，篇数不单独决定能否开始实现。

## 常用请求

| 请求示例 | 对应工作 |
|---|---|
| “按这套流程开始比赛，先讨论大方向。” | 总控了解现有材料，与使用者梳理总体路线 |
| “开Q1，先聊目标和直觉，暂时别算。” | 组织本问研究组，先讨论问题与数据条件 |
| “开Q2，沿用Q1确认的数据与接口。” | 读取前问交接与相关输入，由Q2研究审核方和使用者设计方法 |
| “模型已定，只修改这一段，学习同方法论文的写法。” | 定向参考有关表达，完成局部文字及其一致性检查 |
| “恢复Q1，告诉我当前阶段和下一步。” | 从有效本问卡、简报与接口恢复，不搬运全部历史对话 |

## 共享资料与阶段恢复

保留一份共用资料索引：文件位置、数据来源、关键字段与单位、确认的处理口径和版本。每问记录当前目标、输入、已定方法、结果位置、剩余事项和下一步；前问交接另说明输出可以支持什么判断。

开始新对话时提供这些紧凑材料。遇到定义含糊、版本变化或关键证据疑点，再定向回查原始文件。对话之间共享项目文件不等于共享完整聊天记忆。

## 工具与交付

- [环境检查](task-environment.md) 和 [稿件静态检查](../../author-mathmodel-writing/references/low-level-checks.md) 使用 Python 3.9及以上。
- [个人 LaTeX 模板](../../author-mathmodel-writing/references/current-latex-template.md) 与 [写作案例](../../author-mathmodel-writing/references/writing-examples/index.md) 按任务使用；历史示例不提供新题事实。
- 支持创建、恢复和发消息的环境可按授权组织多对话；其他环境可以手动建立对话并共享交接文件。没有后台机制时，技能不在回合结束后持续调度。
- 网页聊天需要上传材料或使用可用连接，不能仅凭本机路径读取文件。
- 执行完成、独立复核、使用者接受、打包和提交分别记录。静态检查不能替代数学判断、引用核实与实际页面检查。
